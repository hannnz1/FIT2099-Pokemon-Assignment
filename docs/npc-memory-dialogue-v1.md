# NPC 记忆交流阶段

2026-09-30。Java 树果独立场景现在支持 `talk_to(targetNpcId, message)` 和 `wait()`，并在浏览器显示真实 NPC 坐标与最近 8 次交流。默认模型仍为 `gpt-6-luna`。

## 已实现

- 木守宫从真实地图采集附近半径 2 内的树果观察，保存地点、数量、回合和 SELF_OBSERVATION 来源。变化才记入，最多 64 条；查询按本场景与 NPC 隔离，每地点返回最新观察，最多 3 处。
- 对话只允许活动任务中的相邻 NPC，未知对象、超出距离、暂停后的动作、超长消息都会拒绝。回答由 Java 根据真实记忆或规则生成，不额外调用 NPC 模型，也不接受消息中的资产修改指令。
- 博士解释任务要求、期限与状态；商人回答对话当时的库存和价格。询问不扣金币、不增树果，购买仍需独立精确审批。
- 页面保留来源与观察时间，把历史线索与对话时的规则信息明确标注。商店旧报价不会变成当前库存。工具失败后由 Agent 根据实际结果重新决策。
- 会话 Cookie 按实际服务端口命名，避免同时打开多个本机版本时覆盖会话；身份、CSRF、Origin 和 Host 检查继续保留。

## 场景与验证边界

为验证过时线索，开场先让木守宫实际观察果园的 3 个 Berry，再由可信场景初始化把其中同一个 Berry 移到林间。任务开始时实际果园 2 个、林间 1 个。历史 3 个是先前观察，不能保证目前还能拾取 3 个；这属于明确的演示初始条件，不是原世界资源竞争已完成。

离线脚本测试覆盖：询问木守宫 → 根据旧线索拾取 3 个失败 → 实际拾取 2 个 → 询问商人并请求购买 → 玩家拒绝 → 林间取得第 3 个 → 询问博士 → 交付。该测试使用固定模型响应与真实 Java 游戏规则，不能当作真实模型自主决策证明。

全部 Java 测试 128/128，客户端测试 27/27；全部生产代码通过 `javac --release 8` 编译。标准 Maven 流程仍受本机 JDK ZIP 文件系统 AccessDeniedException 影响，未宣称通过。

本机打包版真实 OpenAI Luna 浏览器联调成功：玩家确认“不花金币、不主动战斗”后，模型自主询问木守宫 5 次，页面显示第 0 回合的 3 个树果历史观察与第 5 回合的 0 个更新观察；最终博士实际收到 3 个树果，金币保持 5，位置 (7,1)，第 20 回合完成。此次未触发购买审批，也未调用商人或博士对话；这些分支由上述离线测试覆盖。模型未采用离线脚本，没有额外重试来强迫指定路线。

原世界昼夜与 NPC 自主移动、数据库恢复、区域及自定义期限约束、完整 Trace 和正式验收仍待完成。现在的 MemoryStore 是独立记忆存取，不是游戏存档；本阶段也没有增加数据库持久化。

## 运行

使用本轮 `pokemon-agent-web-npc.jar`，在本机环境已有 `OPENAI_API_KEY` 的终端执行：

```sh
java -jar pokemon-agent-web-npc.jar
```

默认打开 http://127.0.0.1:8088。若旧版占用该端口，在 PowerShell 中先执行 `$env:AGENT_PORT='8089'`，再运行并打开 http://127.0.0.1:8089。不要把密钥写入网页或聊天。

页面没有直接执行任意工具的按钮；模型可以选择询问 NPC 或合法免费路线，不强制每轮重复演示脚本。重启会清空场景，刷新同一正在运行的服务会恢复当前会话。
