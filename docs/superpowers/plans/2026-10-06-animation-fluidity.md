**Goal:** 在保留服务端权威结算和像素风格的前提下，改善新手流程、操作与动画、AI 失败恢复、真实模型评测、历史管理、公开额度、后续目标和网站运行保障。

## 工作包 C：AI 失败与恢复体验（P1）

**范围与文件：** `client/agent/failure-recovery.mjs`、`growth.mjs`、`duel.mjs`、`evaluation-view.mjs`；核对 `src/game/agent/runtime/AgentTask.java`、`AgentLoop.java` 和各 WebRoom 暴露的有限错误码。

| 类型 | 页面解释 | 可用操作 |
|---|---|---|
| 目标未完成/决策上限 | 已完成到哪一步、剩余什么、达到何种上限 | 在规则允许时继续或重新配置；可手动接管 |
| 网络断开/回执未知 | 操作是否提交仍未确认 | 重连、幂等重试；确认前不提交新动作 |
| 模型超时/不可用 | 模型未及时返回或服务不可用 | 保留进度，恢复连接后继续或手动接管 |
| 请求限流 | 请求过于频繁/并发已满 | 显示可重试状态；只有服务端给出时间才展示倒计时 |
| 预算或供应商余额不足 | 区分网站预算与供应商额度 | 停止继续付费调用；支持手动接管，不无限自动重试 |
| 导航受阻/伙伴倒下 | 说明实际路径或体力问题 | 根据状态显示手动移动、返回恢复点或重新规划 |
| 存档失败 | 未确认操作、当前冻结状态 | 保留恢复存档流程，不能直接解锁操作 |

- [ ] 用枚举错误码生成统一解释，不暴露密钥、原始供应商响应或内部路径；证据不足时明确原因待排查。
- [ ] 展示任务目标、实际已交付/已培养进度、最后成功行动和当前卡点；重试不清零已提交进度。
- [ ] 按各模式实际能力展示继续、接管、返程；评测中心的隔离测试结果以查看/重测为主，不能伪造玩家接管接口。
- [ ] 对每一类故障进行可控注入：断线、迟到响应、429、预算耗尽、导航失败、存储失败。确认不重复交付、不重复扣 PP、不继续未知费用请求。

**验收：** 同一原因在不同页面表述一致，按钮与服务器允许状态一致；恢复后历史成果保留。用户能区分“AI 没完成目标”与“服务/额度使测试中止”。
