# Single-player Gameplay Completion Design

Scope agreed by continuation/context: finish three immediate remaining gameplay extensions, not all V2 ideas: selectable battle partner, original-map wild battle/capture, additional native-capturable Mudkip collection. Original V1 peaceful quest remains supported and default. No multiplayer/multi-agent/public hosting/real API change.

Enable field exploration explicitly, spawning one wild Treecko(32,11), Mudkip(34,10), Torchic(36,11). Native NPC Treecko and quest NPCs cannot be attacked or captured. Targets use actual engine Actors, CombatSession and original species capture rules: Treecko/Mudkip capturable, Torchic not. Successful attack/capture/movement consumes exactly one existing world turn; no target warp or free attack on nonadjacent actors. Honor task area and NO_ACTIVE_BATTLE while its task is active/paused. Wild targets stay stationary; counterattacks use original actions. For this controlled quest demo, preflight reject fights when partner cannot survive one possible counterattack, preserving a conscious quest leader/owned companion; show explicit need-to-rest message rather than fabricate invulnerability. Research-area REST heals default leader or recalled owned Pokemon, no coins/turn; deployed Pokemon must be recalled before rest.

Select battle partner: default quest Mudkip or current summoned owned individual. This switches battle attack/capture/movement, not quest collector/interpreter. Commanding owned movement stops following so the owned Actor cannot move twice that turn; Mudkip's original manual controls still control quest leader. No battling against own/transferred/captured targets. Recall/new summon/reset reselect default leader. Partner selection persists only with same generation of active deployment.

Wild capture creates a real trainer Pokeball at stable UUID per wild individual. STORE_WILD target command receives collection first then removes source inventory. Reconcile transferred sources against the single collection authority on snapshot/tick/recover/restart, including uncertain commit; transferred source without matching collection freezes. Source reset permits fresh individuals but not duplicate receipt. Collection capacity20 and original HP range1..100; allow TREECKO/MUDKIP only with native constructors/time-perception cleanup. Torchic never gets an invented capture rule.

Atomic world checkpoint contains complete wild encounter records plus actual deployed owned HP/location/follow flag and battle selection; generation match gates restored owned HP. Collection stores authoritative HP when in-ball; deployed current HP is part of world checkpoint with leader/target damage/turn. Cross-room collection reload must preserve current deployed HP as well as location. Legacy world/collection checkpoints without new fields retain previous behavior. Matching invalid species/HP/position/deployment metadata freezes or rejects without losing collection.

UI includes explore button, wild target/HP/state, battle partner selection, partner movement/attack/capture/store controls, research rest selector. Map markers and all owned labels handle species. Show native Torchic restriction, controlled counterattack health requirement, latest result and restore errors. No real provider calls required; existing OpenAI remains untouched. Build Java8; verify fault recovery, legacy, security/lease/task/revision, captures/HP, native actions, client controls, PostgreSQL, packaged browser capture/store/summon/partner/attack/rest/restart. Deliver complete runtime/source and progress acceptance docs.

Health clarification after review: reserve the next unavoidable DAY15 damage for the quest leader even when an owned partner acts, plus counter damage when leader attacks. Low HP pauses AI before mutation. Emergency REST for an exhausted leader is available remotely without losing wild progress; ordinary collection rest still requires research-area proximity.
