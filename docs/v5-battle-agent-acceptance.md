# V5 对战 Agent：功能与验收（2026-10-05）

V5 本地 Demo 六项功能、离线验收与三种玩法的真实 OpenAI 实网流程验收均已完成。没有更新公网网站。

## 功能范围

| 原计划 | 实现 |
| --- | --- |
| 对战观察 | 本方完整状态、公开对手状态、已展示物种、合法技能与换人；模型观察去除伙伴身份 ID |
| 对战工具 | battle_move / battle_switch，服务器验证 PP、存活、换人槽位与当前行动权 |
| AI 对手 | 玩家选择技能、换人；对手异步决策 |
| AI 队友 | 委托己方出战队伍，可暂停及手动接管 |
| AI 对 AI | 两侧独立观察、隐藏同时选择；共享种子和确定性服务器结算 |
| 对战 Trace | 技能、伤害、PP 消耗、异常阻止行动、回合末伤害、换人、结果；网页回放与 JSON 下载 |
| 评测 | V4 增加 battle 场景、固定种子、规则基线、胜率及 Wilson 95% 区间；结束率与胜率分别统计 |
| 存档恢复 | 独立对战检查点，重启后暂停、命令幂等、保存失败冻结与显式恢复 |

最多每队 3 位伙伴、单打同时在场 1 位；最多 60 战斗回合。复制已有伙伴用于对战，不修改原队伍 HP、PP、经验或捕捉资产。未选择队伍可使用 Lv.20 三只进化伙伴示范队。原有伙伴冒险、委托和训练入口继续保留。

## 限制与费用

本地规则基线不调用收费模型。真实模型只能选服务端已有配置或允许列表，浏览器不接收密钥。单局最多 120 次决策调用，已知累计用量到 250,000 Token 后停止继续发起请求；该值是软阈值，尚未返回的并行请求与最后一次响应可能超过阈值。公开部署的总额度仍依赖现有服务端公共额度管理器。

超时、取消以及重启导致请求用量未知时，界面标记“用量不完整”，不把它计为零费用；阻止继续付费请求，允许手动接管。决策延迟与供应商返回用量可查看；未配置价格时不展示虚构金额。失败不偷偷回退为规则策略。

不包含联网 PvP、完整第三世代机制、道具系统或赛事级对战策略。离线胜率不能代表 LLM 对战能力。

## 验收证据

Java Maven 离线 verify：604 项，583 通过，21 项需独立 PostgreSQL 而跳过，0 失败 / 错误。前端 Node：183 项全部通过。最新 JAR 浏览器验收检查玩家行动、自动对战、暂停继续、回放下载、桌面与手机素材以及溢出 / 控制台报错，浏览器结果见运行包的验收记录目录，源码证据见 benchmarks/2026-10-05/v5。

离线固定种子对比：1–30 相同种子，每种策略 30 局，总计 60 局，全部正常结束，非法动作率 0%。类型/威力规则基线对固定基线获胜 28/30（93.3%，95% CI 78.7%–98.2%）；第一合法技能策略获胜 25/30（83.3%，95% CI 66.4%–92.7%）。示范队与规则对手固定，样本较小且置信区间重叠，不能据此宣称统计显著优势；realAi=false，非实网性能或费用 benchmark。

关键恢复回归覆盖：倒下强制换人后恢复、锁定选择后恢复、仅对战 cookie 的服务器重启、恢复后对手选择仍隐藏、取消未返回用量、保存失败不虚假确认、模型配置退役、超时迟到结果隔离与重复命令不重复执行。

真实模型验收已在用户明确批准后完成。自动审批指出完整伙伴对象可能含额外存档元数据，验收器因此改为严格白名单投影，离线验证后才执行；未绕过审批。只发送物种、等级、HP、技能 PP、合法动作及对战槽位和回合，不发送捕捉 ID、经验、traits、路径、玩家身份或历史存档。具体结果见下节。

## 运行

解压运行包，在安装 Java 的 Windows 上运行“启动游戏.cmd”，访问 http://127.0.0.1:8088/duel/。默认关闭模型，先用规则基线体验；要接入已配置供应商，请在服务器环境中设置 LLM_PROVIDER 和供应商配置后启动。运行包不含凭据和玩家存档。

评测页 http://127.0.0.1:8088/evaluation/ 选择“对战”场景。伙伴冒险 /growth/、和平委托 /quest/、野生训练 /training/ 保留。运行时新增存档在包目录 saves 下；更新现有安装时应保留其 saves，先备份再替换 JAR，不能用空存档覆盖原存档。

## 断网恢复补齐（2026-10-05）

对战页新增“重新连接”和“重试未确认操作”。网络断开或有未确认请求时禁用新操作；重连保留同房间原请求并幂等重发，服务器重启或会话失效导致房间更换时不会重发旧请求。首次连接失败也保留重新连接入口，所有状态以服务器快照为准。

新增三项恢复测试，前端合计 183/183 通过。实际浏览器与最新 JAR 故障验收：让服务器接受一次出招后丢弃响应，点击重试，确认原 payload 相同，最终恰有 1 个战斗回合和 1 条结算 Trace；模拟离线再上线，重新连接成功，0 JavaScript 异常。证据为 benchmarks/2026-10-05/v5/v5-recovery-browser-test.json。

## OpenAI 实网验收（2026-10-05，用户明确批准）

模型 gpt-6-luna，固定 Seed 11、每队三只 Lv.20 示范伙伴。使用实际对战引擎、模型函数调用与 FileWorldStore，无模型侧脚本回退。玩家侧由明确标记的规则驱动逐次提交 ACTION，不是人类水平评测。委托模式对手为公开标记的规则基线，双 AI 模式两侧均是真实模型。

用禁用模型的独立程序重新读取三份真实保存文件：status、world、trace、decisions、tokens、calls 和 usageIncomplete 与实网结束快照一致，三局全部通过。汇总与逐步证据在 benchmarks/2026-10-05/v5/live；复现程序在 tools/V5LiveAcceptance.java 和 tools/V5LiveReloadVerification.java。复现验收会调用收费 API，密钥只从本机环境读取，未包含在源码、报告或运行包。

该结果证明三种流程各跑通一次，不构成模型稳定胜率、完整宝可梦规则或公网负载测试的证明。公网部署仍为另一步。
