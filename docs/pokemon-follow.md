# 召唤木守宫自动跟随

更新：2026-10-01。最新阶段接在携带与召唤功能之后。

解压最新运行包，双击“启动游戏.cmd”，需要 Java 8 或更新版本。打开训练场，向东移动一格，捕捉木守宫并“带回原地图”。返回原地图，选择方向并“召唤宝可梦”，随后点击“开启跟随”。点击“停止跟随”可让木守宫停在当前位置。

## 游戏行为

默认不跟随。开启后，每个实际推进的世界回合最多通过一个真实地图出口。水跃鱼手动行动或 AI 执行有效动作均可带动跟随；“等待一回合”也会推进跟随。仅等待模型、页面刷新、切换开关或暂停期间，不会自行移动或增加回合。跟随不另外花金币、调用模型或推进额外回合。

木守宫以水跃鱼附近的可进入空格为目标，复用已移植的 NavigationService 路线搜索和原游戏 MoveActorAction。原引擎允许斜向出口，因此斜向相邻也算已经靠近。遇到 Actor、墙壁或任务限制会绕行；无可用路线就停留。它不会传送、占据水跃鱼或 NPC 的格子，也不会自动战斗。原地图 NPC 木守宫与“我的木守宫”分别显示。

召唤、收回和开关仍要求当前场景操作权及最新任务/版本。AI 解析、等待确认、运行或等待审批期间，请先结束对应阶段再管理收藏。新一轮委托会自动收回并保留收藏；重新召唤默认关闭跟随。

## 存档

收藏记录决定个体所有权及是否放出；每次新召唤生成独立 deploymentId。收藏坐标是召唤锚点，当前跟随位置和开关与水跃鱼、NPC、回合一起原子保存到委托检查点。恢复只有同时匹配捕捉个体与召唤标识，才使用该检查点的位置。旧的跟随记录不能复活已经收回的个体，也不能覆盖再次召唤的位置。

文件和 PostgreSQL 支持重启恢复；旧收藏/委托存档仍可读取，默认停留。先打开训练场也能看到原地图实际部署位置。跨场景恢复替换实际 Actor 时保持跟随位置并清理旧占位。

保存失败或提交结果不确定会冻结操作。“恢复存档”会读取最后持久化的完整世界；匹配但非法/被占用的位置会继续冻结并保留收藏，请保留存档和备份。保留浏览器 Cookie、保存目录和服务端口，不要降级到旧运行包继续写新版存档。
