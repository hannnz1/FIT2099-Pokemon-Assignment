# 实现规则基线

用户授权：按 `spec.md` 实现 Java 引擎网页化。原工程分支 `feat/phaser-ui`；开发分支 `feat/java-web-demo`。原目录中未提交的 `client` 未覆盖。

原有 15 个 JUnit 测试通过。所有游戏行为仍调用原 Java Action、Pokemon AI、Ground 与 Item；Phaser 不决定移动、命中、血量、物品或回合。

## 保留的实际规则

- Player：1 HP、IMMUNE、TRAINER、TRAINER_POKEBALL。免疫原精灵攻击条件，未添加新战斗系统。
- 八方向合法移动；墙体不可进入，所有其他地形保留 `canActorEnter` 判断。对角移动保留原行为，不额外添加拐角限制。
- 木守宫与水跃鱼可以野外捕获；火稚鸡通过 10 糖果交易获得。没有新增好感门槛、概率捕获、召唤或高级球策略。
- 偏好：木守宫跳舞、水跃鱼唱歌、火稚鸡拍胸脯；喜欢 +10，不喜欢 −20；好感范围 −50～100。
- 交易：GreatBall 3、MasterBall 6、球内 Torchic 10。糖果不足仍为一个已执行回合，但不扣库存。
- 昼夜：1～5 日、6～10 夜，循环。木守宫日 −5 / 夜 +5；水跃鱼日 −15 / 夜 +10；火稚鸡日 +20 / 夜 −15。HP 限制在 0～max。
- 精灵只攻击相邻不同元素且未免疫目标；站在同元素地形上装备原专属武器。
- 博士检查球内三种元素，只提供原有祝贺对话，不新增图鉴物品或任务奖励。

## 保留实际概率，不按注释改平衡

| 行为 | 原判断 | 实际每次试验概率 |
|---|---|---|
| 普通武器命中 | `roll <= 50` | 51% |
| 90 命中武器 | `roll <= 90` | 91% |
| 树生成木守宫 | `roll <= 15` | 16%，逐个草系邻格尝试，成功且空位后停止 |
| 瀑布生成水跃鱼 | `roll <= 20` | 21%，水系邻格累计到 2 后，每个后续匹配邻格均尝试 |
| 火山口生成 | `roll <= 10` | 11% |
| 树掉糖果 | `roll <= 5` | 6% |
| 树扩散 / 树而非草的选择 | `roll <= 10` | 11% |
| 水洼与熔岩变化 | `roll == 10` | 1% |

## 生命周期修复

新局 turn=0，不执行预热 tick。每次合法动作：保留轮初 NPC 列表 → 玩家动作 → 存活且仍在场的 NPC 各一次 → 地图 tick → 收集此刻角色与地形 → 日夜效果 → 清理 → turn/revision +1。

新生精灵同轮可受日夜影响，下轮才执行 AI。替换地形在本轮日夜阶段不递归运行，旧地形对象检查当前位置身份，不继续产生效果。捕获精灵不在活动列表中，球内 HP 与 ID 保留。

死亡不论由攻击或环境造成，统一失去行动资格、掉落可丢弃物品、退出地图。会话回收失效身份、好感与 lastAction 引用。原 singleton API 仅留作旧测试兼容，Web 与当前 Console 入口不使用全局时间/好感状态。

创建、非法请求和读取都不消耗回合。合法业务失败消耗回合。不可预期执行异常将局标记 ENDED，不伪造回滚。

## 演示地图

`maps/demo.tmj` 是唯一编辑源；`node tools/export-map.mjs` 校验尺寸、类型、出生点、占位、可达性、生成邻格条件后导出两端数据与版本。24×18、32 px/格；出生点放置 20 个可拾取糖果，足够展示 3/6/10 三类交易，背包初始为空。精灵、NPC 与环境继续按真实回合运行。
