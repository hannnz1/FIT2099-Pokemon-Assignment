# 地图数量限制与友好 NPC 修复

日期：2026-09-28。用户人工验收后的明确修正，优先于旧规格中固定 20 Candy 和树固定掉落的约定。

## 当前规则

- Treecko、Mudkip、Torchic：每种在当前地图上最多 3 只。初始角色和同轮不同生成点共享限额；背包/球内精灵不计入。捕获或移除后释放名额，后续仍按原地形条件与概率生成，不强制补满 3 只。
- 博士只提供原有对话；商人只提供 3/6/10 Candy 三种交易。两者没有攻击动作，野生 AI 忽略他们，直接 AttackAction 也不伤害友好 NPC。
- Candy：移除出生点 20 颗和树下固定掉落。新局和每次有效世界回合结束后，在玩家可达的空地/草地/地板随机补足至最多 2 颗。候选格无角色、无物品，不在墙、树、水或熔岩中生成；同一次补充不重复选格。
- 已生成的 Candy 保持原位置，直到被拾取，不每回合重新洗牌。玩家当前格有角色，不作为补充候选，因此拾取后不会立即又在脚下出现。
- 上限计算地图上的 Candy 实体总数，而非物品堆或精灵背包数量；玩家背包不限制，交易价格不变。
- 丢下 Candy 必须有地图名额且当前格没有 Candy；满额时动作不提供，底层执行再次检查且不移除背包物品。其他物品丢弃不受此限额影响。死亡掉落使用相同名额限制，不突破上限。
- 无可用位置时跳过补充，不死循环、不把糖果塞入墙中。地图连通性按引擎原有八方向移动判断；固定 NPC 不能成为通路。
- 刷新、菜单和无效请求不推进世界；行动驱动回合规则未改。

## 实现

`WorldPopulation` 统一处理地图计数与 Candy 候选位置；3 类 Spawner 和 DemoMap 的 Pokemon 初始化走同一入口。`GameSession` 在清理退场后补充 Candy。无全局静态数量缓存，避免捕获、死亡和会话切换后失准。

`DropCandyAction` 先复核名额再调用原丢弃动作，`AvailableActionCollector` 不发布已不合法的丢弃。NPC 的动作源头和攻击行为均修复，未仅用前端隐藏按钮。

前端显示当前地图 Candy 数量和坐标，帮助说明同步更新。地图版本 e226ec08457b7ac0；旧服务须重启并开始新局。

## 回归范围

修复前新增 8 个引擎用例中 7 个按预期失败：精灵超额、出生点 20 糖果、无随机补充、树突破上限、NPC 多余动作、满额丢弃等。修复后新增 10 个用例，包含 200 回合地图演化、两个独立世界、捕获释放名额、不可达候选、三类交易产物和背包物品保留。

原物品身份测试改为在有名额时丢弃 Candy；内存回收测试将两颗仍在地图上的 Candy 计入存活对象，不把它们误判为泄漏。真实浏览器测试从地图实际拾取 3 颗随机 Candy 后兑换 GreatBall，并保留博士对话、捕获、刷新、网络重试和会话隔离验证；3/6/10 全部交易产物另由 Java 集成测试验证。
