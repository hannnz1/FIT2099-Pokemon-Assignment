# 单一入口：原地图委托与战斗训练场

更新：2026-10-01。本文记录统一入口阶段；后续已支持 [木守宫带回原地图收藏背包](pokemon-carry.md)，下文“未支持携带”及206项测试属于该历史阶段。

启动 `game.agent.web.AgentWebServer` 或运行包中的“启动游戏.cmd”。默认端口 8088，打开 `http://127.0.0.1:8088/quest/` 进入树果委托，打开 `http://127.0.0.1:8088/training/` 进入训练场。页面顶部可直接切换，不需要启动两个服务。`AGENT_PORT` 可修改端口；`AGENT_MODE` 仅决定根地址和旧 `/api/agent` 接口的默认场景。

后端保持 Java 8；浏览器界面使用原有 JavaScript。AI 沿用本机 `OPENAI_API_KEY` 和默认 `gpt-6-luna`；手动操作不调用模型。运行包不含密钥。

## 切换与存档

同一浏览器会话可拥有两个场景。服务器在同一执行队列中暂停来源任务并切换控制权限；旧标签页不能继续执行、手动移动或发起新委托。重复切换请求返回原收据，不会夺回当前场景的权限。直接打开另一个场景也会暂停原场景。

解析中或等待任务确认时，请先确认或取消任务，再使用页面切换。切换后的未完成任务保持暂停，需要回到该场景手动继续。

两边位置、回合、金币、任务和背包各自保存。训练场保留独立 `battle:` 存档命名空间；原地图存档兼容旧版本。服务器重启后同一端口、浏览器 Cookie 与存档目录可恢复两个场景。继续支持文件及 PostgreSQL 存档。

这次没有将训练场的捕捉宝可梦带回原地图，也没有开启原地图野生战斗。训练场沿用实际引擎：普通球无限、木守宫可直接抓、火稚鸡不可抓。

## 验证记录

本阶段 Java 206/206（含真实隔离 PostgreSQL），客户端 34/34，生产源码 `javac --release 8` 编译通过。测试覆盖两个入口的资源、同会话独立存档、玩家隔离、旧接口兼容、CSRF/Origin、切换期间迟到模型响应、旧标签页恢复请求和重复收据。

打包 JAR 浏览器实测：原地图等待至第 1 回合、金币 5；切换训练场向东移动并捕捉木守宫，第 2 回合、精灵球背包 1；返回原地图仍是第 1 回合、金币 5；服务器重启后两边恢复一致。

本阶段验收使用手动动作与离线模型测试，没有重新调用真实 OpenAI API；之前的 OpenAI 在线捕捉/击败验收记录见 `openai-live-acceptance.md` 和进度文档。本机标准 Maven 构建的历史文件访问限制仍未解决，未宣称 Maven 验证通过。

运行 `scripts/accept-unified-entry.ps1 -BaseUrl http://127.0.0.1:8088` 可重复验证单入口切换与真实库存，不调用模型。真实 OpenAI 验收脚本 `accept-browser-battle.ps1` 默认使用 `/api/training`；旧版独立训练包需传 `-ApiBase /api/agent`。在线脚本会产生 API 用量。
