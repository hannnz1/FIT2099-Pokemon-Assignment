# V3 第一批：原地图独立 NPC Agent（2026-10-02）

## 本批完成范围

火稚鸡、博士、商人已各自接入真实模型循环，与原水跃鱼委托共用权威Java世界。新增原地图火稚鸡NPC Actor与第三世代像素形象。前端新增“多角色协作 · V3”入口、开启/暂停/继续/结束按钮、角色状态、消息及行动记录。旧存档没有V3字段时仍正常加载，未开启时不自动新增NPC或调用模型。

火稚鸡仅观察自身3格范围内的真实树果，可移动一个合法方向；博士观察本任务的需求和真实交付量；商人观察自身库存。消息工具只接受接收者与factId，内容、坐标、观察回合来自服务器已有观察，不接受模型编造消息正文。每个角色只读取自己的观察和收件箱，水跃鱼原委托观察中可读取发给自己的消息，仍须重新检查实际可用资源。消息不是即时世界事实，有来源及过期标记。本批是直接信息传播；多跳转述、复杂长期记忆、Reflection和Daily Planning尚未实现。

NPC决策由工作线程执行，游戏校验和提交由世界线程执行；三个NPC轮询调用，水跃鱼继续使用原委托循环，避免两个控制器争抢水跃鱼。每个NPC最多4次派发（失败也占额度），至多12次NPC模型调用；基础调度记录中的mudkip额度是保留槽位，不表示新增水跃鱼API调用。预算用尽的COMPLETED表示本轮NPC预算结束，不代表树果任务完成。未提供自动补充预算，下一轮需点击“新一轮”。

火稚鸡真实移动推进一个共享世界回合，仍触发原有环境效果；消息和观察不推进回合、不花金币。迟到模型结果的revision不匹配时拒绝；超时、暂停、取消、切换玩法与恢复会丢弃在途结果，不重放动作。解析确认、审批、任务完成/失败阶段会暂停NPC，玩家确认后可手动继续；切换到成长或训练场同步暂停NPC，旧页面不能恢复控制。NPC启动限定原地图新一轮、未开始任务且回合0。

世界、火稚鸡位置、消息收据、消耗预算和角色状态保存在同一房间检查点。文件与真实PostgreSQL恢复均通过，未完成NPC恢复为PAUSED，需要手动继续。存储失败冻结角色，迟到工作线程不能自行提交世界动作。没有实现多NPC同时写世界；世界线程串行提交是本批安全边界。

## 验收

Java400/400通过（含15项真实PostgreSQL）；前端81/81；Maven BUILD SUCCESS（默认15项PG跳过，已在上述真实PG套件全部通过）；生产class兼容Java8。前端资源和34项RPG资源逐字节核对通过。

新增12项Java测试覆盖三个NPC独立调用、消息真实性、角色观察隔离、世界revision失效、超时迟到、暂停取消、非法工具、执行队列拒绝、恢复世界隔离、原地图无回合消息、火稚鸡移动与文件/PG恢复。早期开发发现派发后revision增加会导致自己的结果失效，已修复并重跑上述及全套测试通过。

本机真实OpenAI gpt-6-luna：三个NPC分别发送BERRY/QUEST/OFFER消息，HTTP验收看到三类发送者后主动暂停，无脚本模型回退。切换成长模式后NPC暂停，旧原地图恢复命令被拒绝；重启恢复消息、预算及位置精确一致。

浏览器独立验收：开启NPC协作→三角色4轮共12条真实消息→预算结束→服务器重启→刷新，12条消息与完整记录一致，Phaser地图READY、火稚鸡像素形象正确、控制台无警告/错误。截图与HTTP报告属于隔离会话，不混用个体或状态。本轮真实模型选择了发送消息，火稚鸡移动由Java测试验证，未宣称实网模型执行了移动或完成联合树果任务。

## 运行与试玩

解压pokemon-v3-npc-agent-runtime.zip，双击启动游戏.cmd，打开http://127.0.0.1:8088/quest/。沿用本机OPENAI_API_KEY与gpt-6-luna，包内无密钥、Cookie或个人存档。

在新一轮回合0点击“开启多角色协作”。观察火稚鸡出现在地图，展开“角色消息与行动记录”。角色开始各自思考并发送事实；可暂停、继续或结束。随后可以提交水跃鱼树果委托；解析/确认阶段自动暂停NPC，确认后如需同时行动再点击“继续角色”。购买审批仍属于玩家，NPC不能购买、攻击或改写背包。
