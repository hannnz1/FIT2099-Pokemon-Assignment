## 实测暴露的问题

### 1. 资源竞争 Seed 23：响应解码失败

第 7 次模型请求取得 HTTP 成功与 2,034 Token 的用量记录，但没有产生可执行工具请求，最终为 `PROVIDER_INVALID_RESPONSE`。此前已成功采集 1 个树果并到达备用采集点，最后成功操作是 `observe`。没有发生该案例的预算拦截或寻路失败，不能归因为网络超时、额度不足或旧版本的寻路问题。

现有报告保留了动作、错误类别和用量，**没有原始模型响应**，所以还不能确定是工具调用数量、名称、响应结构或参数 JSON 哪项不符合协议。下一步应补充脱敏的解码失败子原因和可离线回放的结构证据，再对具体分支做回归；不能仅凭此错误码放宽全部校验。

### 2. 训练目标 ID 混用导致多余调用

两条训练轨迹反复把野生宝可梦的 `captureId=091c3811-d614-3964-8599-ebad9baaaa9a` 传给工具的 `targetId`。同一实体可用的遭遇目标 ID 是 `forest-1-0`；使用后者时攻击成功，前者被引擎以 `TARGET_UNAVAILABLE` 拒绝。

- 森林培养有 5 次此类拒绝。
- 故障恢复有 8 次此类拒绝，另有 1 次人为注入的 `UNKNOWN_TOOL`，共 9 次拒绝；不要把全部 9 次都算成人为注入。
- 最终虽然完成，但森林培养消耗 79,186 Token，故障恢复消耗 106,467 Token。

建议优先统一模型观察中的目标标识、在工具说明与当前可用目标中显式给出 `targetId`，对重复无效目标返回明确且有界的纠正反馈。不要让模型继续在两个 ID 之间猜测。这里确认的是“工具参数使用了另一种 ID”，不是对模型内部思维的断言。
